About this lab

Purpose

I'm building Terra — a real climate tech consumer app — using AI as a core part of the design and development process. Not to replace design thinking, but to find exactly where AI creates leverage and where human judgment is irreplaceable. This page is the honest record of that build.

What you'll find here

Real prompts, real outputs, real critique. Each entry captures what was built, the decisions made, what the AI got right and wrong, and what's coming next. No polish — this is the process as it happens.

Why it matters

I'm deliberately moving into climate tech, where complex data and expert users are the norm. Terra is the vehicle — a real product, not a portfolio exercise. AI fluency built through actual shipping is a meaningful differentiator. This is how I build it intentionally, not accidentally.

Tools in rotation

Claude for reasoning, critique, and code generation. Claude Code in VS Code for building components and pages. Figma as the source of truth. Other tools introduced deliberately — only when a specific gap appears.

My approach

How the build works

01 —

PM first

Before any screen gets designed, the problem gets defined. JTBD, competitor research, user assumptions. AI accelerates the research; the thinking is still mine.

02 —

Build with Claude

Design and code happen together. Claude generates HTML/CSS, I critique and iterate. Ship working screens first — Figma comes after, not before.

03 —

Refine in Figma

Built output routes back to Figma for design system compliance, accessibility checks, and variant work. Figma is the source of truth, not the starting point.

04 —

Ship and log

Working code gets deployed. Every session gets logged here — what shipped, what broke, what the AI got wrong, and what the next step is.

#002 May 2026
Product Design Claude HTML/CSS Vercel

Designing and shipping Terra's sign-up flow in one session

First real build session for Terra. Starting point was an existing sign-up prototype — the work was equal parts design critique, visual system decisions, and iterative building. Established the full colour palette (beige + pine green), botanical visual language, and UX patterns. Went from rough prototype to live deployed product in a single session.

Tool used

Claude Sonnet

Type

Consumer app / Auth flow

Time to shipped

~2 hours

→

Outcome: Shipped a live sign-up flow at terra-beige-mu.vercel.app — full palette system, paper grain texture, botanical photo as decorative element, back navigation with reverse animation, 3-step progress indicator, and password strength checker. Next: proper repo structure and PM foundations (JTBD, competitor research). Key insight: sharing a photo reference produced better colour decisions in one round than describing the palette in words across three.

#001 May 2026
Workflow Claude Portfolio

Building my AI lab page from scratch with Claude

Challenge: design and build a portfolio sub-page that documents my AI workflow experiments — without opening Figma first. Starting point was a brief description of intent and a link to my existing portfolio. Goal was to ship a visually cohesive, production-ready page that matches my existing aesthetic while solving a real information architecture problem.

Tool used

Claude Sonnet

Challenge type

Page design & IA

Time to first draft

~15 minutes

→

Outcome: Claude fetched the live portfolio URL, extracted the visual language (dark bg, monospace accents, editorial typography), and generated a fully structured HTML page matching the aesthetic. Key insight: giving Claude a live URL produces dramatically better visual alignment than describing the style in words. The IA structure also came out cleanly on the first pass because the brief was specific about the content types needed.
